Le CLI `yarn diex` est votre interface pour tout ce qui concerne les applications. Liste complète des commandes :

| ----------------------------------------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `dev`                                           | Surveille les fichiers sources et synchronise en direct les modifications                 | [Prise en main rapide](/l/fr/developers/extend/apps/getting-started/quick-start)                                     |
| `plan`                                          | Prévisualiser les modifications de métadonnées sans les appliquer                         | [Synchronisation et récupération](/l/fr/developers/extend/apps/operations/sync-and-recovery#previewing-changes-plan) |

Chaque commande accepte `-r, --remote \<name>` pour cibler un serveur distant spécifique au lieu de celui par défaut.

## Exécuter des fonctions (`yarn diex dev:function:exec`)

Exécutez une fonction logique manuellement sans la déclencher via HTTP, cron ou un événement de base de données :

```bash filename="Terminal"
# Execute by function name
yarn diex dev:function:exec -n create-new-post-card

# Execute by universalIdentifier
yarn diex dev:function:exec -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf

# Pass a JSON payload
yarn diex dev:function:exec -n create-new-post-card -p '{"name": "Hello"}'

# Execute the install and uninstall hooks
yarn diex dev:function:exec --postInstall
yarn diex dev:function:exec --preInstall
yarn diex dev:function:exec --uninstall
```

## Afficher les journaux des fonctions (`yarn diex dev:function:logs`)

Diffuser en continu les journaux d'exécution des fonctions logiques de votre application :

```bash filename="Terminal"
# Stream all function logs
yarn diex dev:function:logs

# Filter by function name
yarn diex dev:function:logs -n create-new-post-card

# Filter by universalIdentifier
yarn diex dev:function:logs -u e56d363b-0bdc-4d8a-a393-6f0d1c75bdcf
```

<Note>
Ceci est différent de `yarn diex docker:logs`, qui affiche les journaux du conteneur Docker. `yarn diex dev:function:logs` affiche les journaux d'exécution des fonctions de votre application depuis le serveur Diex.
</Note>

## Génération du client typé (`yarn diex dev:generate-client`)

Régénérez le client API typé (`diex-client-sdk`) à partir du schéma du remote actif, sans compiler ni synchroniser une application. Utilisez-le pour obtenir un client typé dans n’importe quel projet — comme un service back-end hébergé dans un dépôt distinct — qui communique avec votre instance Diex :

```bash filename="Terminal"
# In your project (no Diex app definition required)
yarn add diex-sdk diex-client-sdk

# Connect to the Diex instance to generate the client from
yarn diex remote:add

# Generate the typed client into node_modules/diex-client-sdk
yarn diex dev:generate-client
```

Puis importez le client dans votre code :

```typescript
import { CoreApiClient } from 'diex-client-sdk/core';
```

Relancez la commande chaque fois que votre modèle de données change afin d’actualiser les types générés.

<Note>
Le client est généré dans `node_modules`, il n’est donc pas versionné avec votre code. Exécutez `yarn diex dev:generate-client` après chaque installation (par exemple dans un script `postinstall` ou dans un pipeline CI).
</Note>

## Désinstaller une application (`yarn diex app:uninstall`)

Supprimez votre application de l'espace de travail actif :

```bash filename="Terminal"
yarn diex app:uninstall

# Skip the confirmation prompt
yarn diex app:uninstall --yes
```

## Gestion des remotes

Un remote est un serveur Diex auquel votre application se connecte. Lors de la configuration, le générateur en crée un automatiquement pour vous. Vous pouvez ajouter d’autres remotes ou basculer entre eux à tout moment.

```bash filename="Terminal"
# Add a new remote (opens a browser for OAuth login)
yarn diex remote:add

# Connect to a local Diex server (auto-detects port 2020 or 3000)
yarn diex remote:add --local

# Add a remote non-interactively (useful for CI)
yarn diex remote:add --url https://your-diex-server.com --api-key $DIEX_API_KEY --as my-remote

# List all configured remotes
yarn diex remote:list

# Set the active remote
yarn diex remote:use <name>

# Check that the active remote's authentication is still valid
yarn diex remote:status

# Remove a remote
yarn diex remote:remove <name>
```

Vos identifiants sont stockés dans `~/.diex/config.json`.
