## Gerenciando o servidor local

Use `yarn diex docker:*` para controlar o contêiner Diex local:

| Comando                                | O que faz                                        |
| -------------------------------------- | ------------------------------------------------ |
| `yarn diex docker:start`             | Inicia o servidor (baixa a imagem se necessário) |
| `yarn diex docker:start 2.2.0`       | Iniciar uma versão específica do servidor        |
| `yarn diex docker:start --port 3030` | Inicia em uma porta personalizada                |
| `yarn diex docker:stop`              | Interrompe o servidor (preserva os dados)        |
| `yarn diex docker:status`            | Mostra a URL, a versão e as credenciais de login |
| `yarn diex docker:logs`              | Transmite os logs do servidor                    |
| `yarn diex docker:reset`             | Apaga os dados e começa do zero                  |
| `yarn diex docker:upgrade`           | Baixa a imagem mais recente `diex-app-dev`     |
| `yarn diex docker:upgrade 2.2.0`     | Atualiza para uma versão específica              |

Os dados são persistidos entre reinicializações em dois volumes do Docker (`diex-app-dev-data` para PostgreSQL, `diex-app-dev-storage` para arquivos). Use `reset` para apagar tudo.

## Fixando a versão do servidor

Quando nenhuma versão é passada, `docker:start` resolve a versão a partir do intervalo `engines.diex` do seu app em `package.json` — o mesmo intervalo que o servidor valida quando o seu app é instalado. Ele inicia a imagem mais recente publicada de `diex-app-dev` que satisfaz o intervalo, recorrendo a `latest` quando o campo está ausente ou nenhuma versão publicada corresponde:

```json filename="package.json"
{
  "engines": {
    "diex": ">=2.2.0"
  }
}
```

Passe uma versão explicitamente para substituir o intervalo em uma única execução: `yarn diex docker:start 2.3.0`. Se já existir um contêiner em uma versão diferente, `docker:start` faz o upgrade dele no lugar (recriando o contêiner enquanto preserva seus volumes de dados).

## Atualizando a imagem do servidor

`yarn diex docker:upgrade` baixa a imagem mais recente, compara os digests e só recria o contêiner se algo realmente tiver mudado. Os volumes são preservados — apenas o contêiner é substituído. Se uma nova imagem foi baixada e o contêiner estava em execução, a atualização inicia automaticamente um novo contêiner; execute `yarn diex docker:start` depois para aguardar até que ele fique saudável.

```bash filename="Terminal"
yarn diex docker:upgrade            # Latest
yarn diex docker:upgrade 2.2.0      # Specific version
```

Verifique a versão em execução com `yarn diex docker:status` (ele mostra o `APP_VERSION` incorporado ao contêiner).

## Executando uma instância de teste paralela

Passe `--test` para qualquer comando `docker:*` para gerenciar uma segunda instância totalmente isolada — útil para testes de integração ou para experimentar sem tocar nos seus dados principais de desenvolvimento:

| Comando                             | O que faz                                        |
| ----------------------------------- | ------------------------------------------------ |
| `yarn diex docker:start --test`   | Inicia a instância de teste (padrão: porta 2021) |
| `yarn diex docker:stop --test`    | Para                                             |
| `yarn diex docker:status --test`  | Mostra seu status                                |
| `yarn diex docker:logs --test`    | Transmite seus logs                              |
| `yarn diex docker:reset --test`   | Apaga seus dados                                 |
| `yarn diex docker:upgrade --test` | Atualiza sua imagem                              |

A instância de teste tem seu próprio contêiner (`diex-app-dev-test`), volumes (`diex-app-dev-test-data`, `diex-app-dev-test-storage`) e configuração — ela é executada junto com sua instância principal sem conflitos. Combine `--test` com `--port` para substituir 2021.

## Configuração manual (sem o gerador)

Ignore o gerador se você estiver adicionando o SDK a um projeto existente:

```bash filename="Terminal"
yarn add diex-sdk diex-client-sdk
```

Adicione o script ao `package.json`:

```json filename="package.json"
{
  "scripts": {
    "diex": "diex"
  }
}
```

Agora você pode executar `yarn diex dev`, `yarn diex docker:start` e o restante.

<Note>
Não instale `diex-sdk` globalmente — fixe-o por projeto, para que cada aplicativo use sua própria versão.
</Note>
